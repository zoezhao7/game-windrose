Windrose unterstützt Drop-in/Drop-out-Koop, aber für einen persistenten Crew-Speicherstand brauchst du einen dedizierten Server. Dieser Leitfaden verwandelt den offiziellen Einrichtungsablauf in eine vollständige Pre-Launch-Checkliste: SteamCMD-Installation, server.cfg-Referenz, Port-Mapping, Firewall-Regeln und eine Fehlerbehebungsliste für die Verbindungsprobleme, auf die Spieler am häufigsten stoßen.

Wer sollte einen dedizierten Server betreiben?

Wenn du nur mit ein oder zwei Freunden am selben Abend spielst, reicht das Hosten aus dem Spiel-Client heraus völlig. Ein dedizierter Server lohnt sich, sobald die Welt online bleiben soll, während du offline bist, du drei oder mehr Spieler in unterschiedlichen Zeitzonen hast oder du Backups und Patch-Zeitpunkte selbst kontrollieren willst. Der Preis dafür: ein dauerhaft laufender Windows-Rechner, ein paar Firewall- und Router-Ausnahmen und gelegentlich ein app_update nach einem Steam-Patch.

SteamCMD-Installationsbefehle

SteamCMD ist der empfohlene Weg für eine Headless-Installation. Lade SteamCMD aus dem Valve Developer Wiki herunter, entpacke es an einen festen Ort wie C:\steamcmd und starte steamcmd.exe. Führe dann die vier Befehle unten in dieser Reihenfolge aus. Der erste Lauf ist ein vollständiger Download (mehrere Gigabyte); spätere Läufe holen nur Änderungen.

force_install_dir "C:\Game_Servers\Windrose_Server"
login anonymous
app_update 4129620 validate
quit

Nach dem Beenden des Skripts liegen die Binärdateien unter C:\Game_Servers\Windrose_Server. Öffne den Ordner und prüfe, dass WindroseServer.exe existiert, bevor du weitermachst. Steam legt daneben ein kleines steamapps-Manifest an; nicht löschen.

Aktualisieren nach einem Patch

Sobald Windrose einen Client-Patch veröffentlicht, starte SteamCMD neu und führe app_update 4129620 validate erneut aus. Der Schalter validate prüft Datei-Hashes neu und behebt die meisten "Server startet, aber Clients können nicht beitreten"-Probleme nach einem halb fertigen Update. Halte die Server-Version mit dem aktuellen Client-Build abgestimmt; Clients mit neuerem Build werden abgelehnt.

server.cfg Feldreferenz

Die meisten Servereinstellungen liegen in einer einzigen Konfigurationsdatei, die beim ersten Start im Save-Ordner des Servers angelegt wird. Die folgenden Felder sind die, die Spieler tatsächlich anpassen. Bearbeite sie, während der Server heruntergefahren ist, und starte ihn dann neu, damit die Werte von der Festplatte neu geladen werden.

Port-Mapping & NAT

Windrose-Server nutzen standardmäßig NAT-Punch-Through, daher funktionieren die meisten Heim-Router ohne Port-Forwarding, solange UPnP aktiv ist. Wenn dein Router kein UPnP unterstützt oder du den Server hinter einer Firmenfirewall betreibst, musst du die unten aufgelisteten Ports manuell weiterleiten. Deaktiviere Proxy- und VPN-Software beim ersten Verbindungstest; beides bricht NAT-Punch-Through, selbst wenn die Ports offen sind.

Standard-Ports des Windrose Dedicated Servers
PortProtokollZweck
7777UDPSpiel-Traffic zwischen Server und Clients
27015UDPSteam-Master-Server-Abfrage (Sichtbarkeit im Serverbrowser)
27016UDPOptionales Steam-Query-Backup; nur weiterleiten, falls 27015 belegt ist

Firewall- & Antivirus-Regeln

Die Windows Defender Firewall blockiert unsignierte Game-Server standardmäßig. Beim ersten Start von WindroseServer.exe fragt Windows, ob die Datei in privaten und öffentlichen Netzwerken zugelassen werden soll; klicke für beide auf "Zugriff zulassen". Falls du diese Eingabeaufforderung verpasst hast oder unbeaufsichtigt läufst, lege die Regel manuell an:

  1. Öffne Windows-Sicherheit → Firewall- & Netzwerkschutz → App durch Firewall zulassen.
  2. Klicke auf Einstellungen ändern, dann Andere App zulassen… und wähle WindroseServer.exe.
  3. Hake sowohl Privat als auch Öffentlich an und bestätige mit OK.
  4. Wenn du eine Drittanbieter-Antivirus-Lösung nutzt, füge den gesamten Ordner C:\Game_Servers\Windrose_Server zur Ausschlussliste hinzu — manche AV-Engines flaggen Game-Server als verdächtig, weil sie auf UDP-Ports lauschen.
  5. Aktiviere auf der Router-Seite UPnP oder leite UDP 7777 und 27015 manuell auf die LAN-IP des Servers weiter, falls UPnP nicht verfügbar ist.

Grundlegender Einrichtungsablauf

  1. Installiere das dedizierte Server-Paket über SteamCMD oder Steam-Tools.
  2. Konfiguriere Servername, Passwort, Region, Spielerzahl und Speicherverhalten, während der Server heruntergefahren ist.
  3. Stelle sicher, dass UPnP für NAT-Punch-Through verfügbar ist, und deaktiviere dann Proxy oder VPN während der ersten Verbindungstests.
  4. Füge Firewall- und Antivirus-Ausnahmen für WindroseServer.exe hinzu.
  5. Starte den Server, teste die Verbindung von einem separaten Client und sichere Speicherstände vor größeren Patches.

Häufige Verbindungsprobleme

Die meisten gemeldeten Probleme fallen in dieselben fünf Kategorien. Arbeite sie der Reihe nach durch; die ersten drei lösen rund 80 % der gescheiterten Verbindungen.

  • "Verbindung fehlgeschlagen" / "Zeitüberschreitung" — Bestätige zuerst, dass der Server-Prozess wirklich läuft und die Konsole Server started zeigt. Prüfe dann, ob der Spieler denselben Client-Build wie der Server nutzt — ein app_update-Versatz auf einer Seite erzeugt diesen Fehler. Führe auf beiden Seiten app_update 4129620 validate erneut aus und versuche es dann nochmal.
  • Server erscheint nicht im Ingame-Browser — Fast immer ein Steam-Query-Port-Problem. Stelle sicher, dass UDP 27015 eingehend offen ist, dass kein anderes Steam-Spiel bereits 27015 auf demselben Rechner belegt, und dass die Region des Suchenden auf "Beliebig" steht. Wenn der Server im LAN-Tab erscheint, aber im Internet-Tab nicht, liegt es am NAT/UPnP.
  • Freunde verbinden sich, Fremde nicht — Freunde nutzen das Steam-Relay; Fremde gehen über NAT-Punch-Through. Wenn nur Freunde reinkommen, blockt der Router eingehende UDP auf 7777. Aktiviere UPnP oder lege eine manuelle Port-Forwarding-Regel an und deaktiviere alle Proxy-/VPN-Programme auf dem Host.
  • Welt-Speicherstand leer oder zurückgesetzt nach Neustart — Prüfe, dass AutoSaveOnExit auf true steht und der Server Schreibrechte im Save-Verzeichnis hat. Wenn du den Server aus Programme heraus startest, kann Windows UAC Schreibvorgänge stillschweigend in einen Virtual-Store umleiten. Lege den Server unter einem normalen Pfad wie C:\Game_Servers ab.
  • Server wird nach einigen Stunden langsam — Meist Speicherdruck, wenn MaxPlayers höher gesetzt ist, als der Host stemmen kann. Senke den Wert oder plane einen nächtlichen Neustart über die Aufgabenplanung. Sichere den Save-Ordner vor Änderungen.

Häufig gestellte Fragen

Kann ich einen Windrose Dedicated Server hosten?

Ja. Der offizielle Leitfaden unterstützt die SteamCMD-Installation mit App-ID 4129620 und gibt den aktuellen Konfigurations-Workflow vor.

Läuft der dedizierte Server auf Linux?

Der offizielle Leitfaden beschreibt ihn derzeit als Windows-only, daher behandle Linux- oder Headless-Setups als nicht unterstützt, sofern sich die offizielle Dokumentation nicht ändert.

Sollte ich mein Server-Save sichern?

Ja. Sichere vor Patches, vor Änderungen der Schwierigkeit oder der Welt-Einstellungen und vor dem Wechsel des Hosts.

Welche Ports nutzt Windrose?

UDP 7777 für den Spiel-Traffic und UDP 27015 für die Steam-Serverbrowser-Abfrage. UPnP regelt das auf den meisten Heim-Routern automatisch; wenn UPnP deaktiviert ist, leite beide Ports manuell auf die LAN-IP des Servers weiter.

Warum findet niemand meinen Server im Browser?

Fast immer ein UDP-27015-Problem: ein anderer Steam-Prozess hat den Port belegt, die Firewall blockiert ihn oder der Regionsfilter des Spielers schließt deinen Server aus. Prüfe die Firewall-Regel, gib Port 27015 frei und stelle den Browser-Regionsfilter des Spielers auf "Beliebig".

Wie viele Spieler verträgt ein dedizierter Server?

Praktisches Limit auf einem typischen Heim-Host sind 4–8 gleichzeitige Spieler. Höher braucht mehr CPU-Kerne und mindestens 25 Mbit/s Upload; MaxPlayers über das Mögliche hinaus zu setzen, verursacht Desync statt einer sauberen Fehlermeldung.
